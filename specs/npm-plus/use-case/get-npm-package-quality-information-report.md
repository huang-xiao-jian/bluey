# 获取 npm package 质量信息报告

## 参与者

- **主要参与者：** **开发者**

## 简要说明

开发者获取特定 npm package 的客观质量信息，并自行判断该 package 是否适合使用，尤其用于核验 AI 推荐的 package。

## 前置条件

1. 开发者已经确定一个需要了解的 npm package。

## 事件流

### 基本事件流

1. 开发者使用 package 名称以及可选的精确版本号或 tag 请求质量信息报告。
2. 系统按照版本确定规则将请求解析为目标 package 和精确版本。
3. 系统确认目标 package 和精确版本存在。
4. 系统返回完整报告；报告标明目标 package、精确版本，并包含规定质量维度上的客观信息。
5. 开发者接收报告，并自行评价该 package。

### 备选事件流

#### 未指定版本标识

1. 当开发者只提交 package 名称时，系统使用 `latest` tag 确定目标版本。
2. 系统在报告中标明 `latest` tag 及其对应的精确版本。
3. 系统继续返回目标版本的完整报告。

#### 使用 tag 指定版本

1. 当开发者提交 package 名称和 tag 时，系统使用该 tag 确定目标版本。
2. 系统在报告中标明该 tag 及其对应的精确版本。
3. 系统继续返回目标版本的完整报告。

#### package 不存在

1. 当系统确认指定的 package 不存在时，系统返回报告，将 package 不存在作为报告事实。
2. 系统不在报告中提供质量维度信息。
3. 用例结束。

#### 精确版本不存在

1. 当系统确认 package 存在但指定的精确版本不存在时，系统返回报告，仅说明该版本不存在。
2. 系统不在报告中提供 package 层面或质量维度的信息。
3. 用例结束。

#### tag 不存在或无法解析

1. 当系统确认 package 存在但指定的 tag 不存在或无法解析时，系统返回报告，仅说明该 tag 无法确定目标版本。
2. 系统不在报告中提供 package 层面或质量维度的信息。
3. 用例结束。

### 异常事件流

#### 报告信息不完整

1. 当目标 package 和精确版本存在，但任一必需质量维度的信息缺失时，系统说明无法形成完整报告。
2. 系统不生成报告。

## 后置条件

**成功场景：**

1. 系统已经返回一份报告。
2. 当目标 package 和精确版本存在时，报告包含全部规定质量维度的客观信息。
3. 当 package、精确版本或 tag 不存在时，报告包含相应的不存在事实，并构成针对该请求的完整报告。
4. 报告不包含评分、评级、采用建议或其他评价性结论。

**失败场景：**

1. 系统没有生成报告。
2. 系统已经说明报告信息不完整。
3. 系统没有使用信息不完整的报告代替失败结果。

## 业务规则

- **支持的 package 标识方式**：系统接受 package 名称、package 名称加精确版本号、package 名称加 tag 三种标识方式。
- **默认版本**：只提供 package 名称时，系统使用 `latest` tag 对应的版本。
- **不存在属于报告事实**：package、精确版本或 tag 不存在时，系统生成报告，并将不存在作为报告内容。
- **不存在报告的完整性**：package、精确版本或 tag 不存在这一事实构成针对该请求的完整报告；系统不要求该报告包含其他质量维度的信息。
- **质量信息维度**：目标 package 和精确版本存在时，报告必须包含安全性、维护状况、流行度、文档质量、许可证、依赖风险和供应链可信度信息。
- **客观信息约束**：报告只呈现客观信息，不进行评分、评级、价值判断或采用建议。
- **完整性要求**：默认情况下，任一必需质量维度的信息缺失时，系统不得生成报告。
- **评价责任**：开发者负责评价 package 质量并决定是否采用该 package。
- **用例边界**：AI 如何使用报告、package 横向比较和替代 package 推荐不属于本用例。

## 特殊需求

无。

## 扩展点（可选）

- **版本范围表达式**：支持使用版本范围表达式指定目标版本。
- **接收信息缺失的报告**：允许开发者声明可以接收信息缺失的报告；启用后，系统可以返回报告并明确标识缺失内容。
