# 获取 npm package 质量信息报告

## 参与者

- **主要参与者：** 开发者

## 简要说明

开发者获取特定 `npm package` 的客观质量信息，并自行判断该 `package` 是否适合使用。

## 前置条件

无

## 事件流

### 基本事件流

1. 开发者使用 `package name` 以及可选的 **精确版本号** 或 `tag` 请求质量信息报告。
2. 系统按照版本确定规则将请求解析为目标 `package` 和 **精确版本号**。
3. 系统确认目标 `package` 和精确版本存在。
4. 系统返回报告；报告标明目标和规定质量维度上的客观信息。
5. 开发者接收报告，并自行评价该 `package`。

### 备选事件流

#### 未指定版本标识

1. 当开发者只提交 `package` 名称时，系统使用 `latest tag` 确定目标版本。
2. 系统在报告中标明 `latest tag` 及其对应的精确版本。
3. 系统继续返回目标版本的报告。

#### 使用 tag 指定版本

1. 当开发者提交 `package` 名称和 `tag` 时，系统使用该 `tag` 确定目标版本。
2. 系统在报告中标明该 `tag` 及其对应的精确版本。
3. 系统继续返回目标版本的报告。

#### package 不存在

1. 当系统确认指定的 `package` 不存在时，系统返回报告，将 `package` 不存在作为报告事实。
2. 系统不在报告中提供质量维度信息。
3. 用例结束。

#### 精确版本不存在

1. 当系统确认 `package` 存在但指定的精确版本不存在时，系统返回报告，仅说明该版本不存在。
2. 系统不在报告中提供 `package` 层面或质量维度的信息。
3. 用例结束。

#### tag 不存在或无法解析

1. 当系统确认 `package` 存在但指定的 `tag` 不存在或无法解析时，系统返回报告，仅说明该 `tag` 无法确定目标版本。
2. 系统不在报告中提供 `package` 层面或质量维度的信息。
3. 用例结束。

## 后置条件

**成功场景：**

1. 当目标 package 和精确版本存在时，报告呈现系统能够获得的规定质量维度客观信息。
2. 当 package、精确版本或 tag 不存在时，报告包含相应的不存在事实。
3. 报告不包含评分、评级、采用建议或其他评价性结论。

## 业务规则

- **支持的 package 标识方式**：系统接受 package 名称、package 名称加精确版本号、package 名称加 tag 三种标识方式。
- **默认版本**：只提供 package 名称时，系统使用 `latest` tag 对应的版本。
- **不存在的处理**：package、精确版本或 tag 不存在或无法解析时，系统生成报告，将相应事实作为报告内容，不提供不适用的质量维度信息。
- **质量信息维度**：目标 package 和精确版本存在时，系统围绕安全性、维护状况、流行度、文档质量、许可证、依赖风险和供应链可信度等维度收集并呈现可获得的信息。
- **客观信息约束**：报告只呈现客观信息，不进行评分、评级、价值判断或采用建议。
- **评价责任**：开发者负责评价 package 质量并决定是否采用该 package。
- **用例边界**：AI 如何使用报告、package 横向比较和替代 package 推荐不属于本用例。

## 特殊需求

无。
