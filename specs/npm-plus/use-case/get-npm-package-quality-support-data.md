# 获取 npm package 质量支撑数据

## 参与者

- **主要参与者：** 开发者

## 简要说明

开发者获取特定 `npm package` 的客观质量支撑数据，并自行判断该 `package` 是否适合使用。

## 前置条件

无

## 事件流

### 基本事件流

1. 开发者使用 `package name` 以及可选的**精确版本号**或 `tag` 请求质量支撑数据。
2. 系统按照版本确定规则将请求解析为目标 `package` 和**精确版本号**。
3. 系统确认目标 `package` 和精确版本存在。
4. 系统提供检查目标及其在规定质量维度上的可用原始质量数据。
5. 开发者依据质量支撑数据自行评价该 `package`。

### 备选事件流

#### 未指定版本标识

1. 当开发者只提交 `package` 名称时，系统使用 `latest tag` 确定目标版本。
2. 系统在检查目标中保留 `latest tag` 及其对应的精确版本。
3. 系统继续提供目标版本的质量支撑数据。

#### 使用 tag 指定版本

1. 当开发者提交 `package` 名称和 `tag` 时，系统使用该 `tag` 确定目标版本。
2. 系统在检查目标中保留该 `tag` 及其对应的精确版本。
3. 系统继续提供目标版本的质量支撑数据。

#### package 不存在

1. 当系统确认指定的 `package` 不存在时，系统提供 `package` 不存在的目标确定结果。
2. 系统不提供检查目标或质量支撑数据。
3. 用例结束。

#### 精确版本不存在

1. 当系统确认 `package` 存在但指定的精确版本不存在时，系统提供精确版本不存在的目标确定结果。
2. 系统不提供 `package` 层面信息、检查目标或质量支撑数据。
3. 用例结束。

#### tag 不存在或无法解析

1. 当系统确认 `package` 存在但指定的 `tag` 不存在或无法解析时，系统提供对应的目标确定结果。
2. 系统不提供 `package` 层面信息、检查目标或质量支撑数据。
3. 用例结束。

## 后置条件

**目标确定成功：**

1. 系统提供已经确定精确版本的检查目标。
2. 系统提供能够获得的规定质量维度原始质量数据。
3. 质量支撑数据不包含评分、评级、采用建议或其他评价性结论。

**目标确定失败：**

1. 系统提供对应的不存在或无法解析事实。
2. 系统不提供不适用的检查目标或质量支撑数据。

## 业务规则

- **支持的 package 标识方式**：系统接受 package 名称、package 名称加精确版本号、package 名称加 tag 三种标识方式。
- **默认版本**：只提供 package 名称时，系统使用 `latest` tag 对应的版本。
- **目标确定失败处理**：package、精确版本或 tag 不存在或无法解析时，系统提供相应事实，不提供不适用的检查目标或质量支撑数据。
- **质量信息维度**：目标 package 和精确版本存在时，系统围绕已经正式定义的质量维度收集并提供可获得的原始质量数据；当前正式定义的维度为依赖规模。
- **客观信息约束**：质量支撑数据只包含客观事实，不进行评分、评级、价值判断或采用建议。
- **评价责任**：开发者负责评价 package 质量并决定是否采用该 package。
- **用例边界**：质量支撑数据的报告格式、呈现方式和传递方式，以及 AI 如何使用数据、package 横向比较和替代 package 推荐，不属于本用例。

## 特殊需求

无。
