# 检查 npm package 质量

## 参与者

- **主要参与者：** 开发者

## 简要说明

开发者检查特定 `npm package` 的质量，获得规定质量维度上的客观事实，并自行判断该 `package` 是否适合使用。

## 前置条件

无

## 事件流

### 基本事件流

1. 开发者使用 `package name` 以及可选的 **精确版本号** 或 `tag` 请求检查 `package` 质量。
2. 系统按照版本确定规则将请求解析为目标 `package` 和 **精确版本号**。
3. 系统确认目标 `package` 和精确版本存在。
4. 系统检查目标 `package` 在每个规定质量维度上的质量。
5. 系统提供检查目标以及各质量维度的检查结果。

### 备选事件流

#### 未指定版本标识

1. 当开发者只提交 `package` 名称时，系统使用 `latest tag` 确定目标版本。
2. 系统在检查目标中保留 `latest tag` 及其对应的精确版本。
3. 系统继续检查目标版本的质量。

#### 使用 tag 指定版本

1. 当开发者提交 `package` 名称和 `tag` 时，系统使用该 `tag` 确定目标版本。
2. 系统在检查目标中保留该 `tag` 及其对应的精确版本。
3. 系统继续检查目标版本的质量。

#### package 不存在

1. 当系统确认指定的 `package` 不存在时，系统抛出 `PackageNotFound`。
2. 用例失败，不提供质量检查结果。

#### 精确版本不存在

1. 当系统确认 `package` 存在但指定的精确版本不存在时，系统抛出 `ExactVersionNotFound`。
2. 用例失败，不提供质量检查结果。

#### tag 不存在或无法解析

1. 当系统确认 `package` 存在但指定的 `tag` 不存在时，系统抛出 `TagNotFound`；tag 映射的精确版本不存在时，系统抛出 `TagUnresolvable`。
2. 用例失败，不提供质量检查结果。

#### 质量维度评估异常

1. 当系统已经确定检查目标，但评估某个质量维度时发生异常，系统将异常转换为该维度的失败评估。
2. 系统继续评估其他规定质量维度。
3. 系统提供包含成功数据与失败评估的质量检查结果。

## 后置条件

**质量检查成功：**

1. 系统完成目标确定，并在检查结果中提供已经确定精确版本的检查目标。
2. 系统在检查结果中为每个规定质量维度提供成功的原始质量数据或失败评估。
3. 质量检查结果不包含评分、评级、采用建议或其他评价性结论。

**目标确定失败：**

1. 系统抛出对应的目标确定错误。
2. 系统不提供质量检查结果。

## 业务规则

- **支持的 package 标识方式**：系统接受 package 名称、package 名称加精确版本号、package 名称加 tag 三种标识方式。
- **默认版本**：只提供 package 名称时，系统使用 `latest` tag 对应的版本。
- **目标确定失败处理**：package、精确版本或 tag 不存在或无法解析时，系统抛出相应错误，不提供质量检查结果。
- **质量评估异常处理**：确定检查目标后，质量维度评估异常必须内建于**InspectTargetQuality**的对应维度结果中，不得导致其他维度的成功数据丢失。
- **质量信息维度**：目标 package 和精确版本存在时，系统围绕已经正式定义的质量维度收集并提供可获得的原始质量数据；当前正式定义的维度为依赖规模。
- **客观信息约束**：质量检查结果只包含客观事实，不进行评分、评级、价值判断或采用建议。
- **评价责任**：开发者负责评价 package 质量并决定是否采用该 package。
- **用例边界**：质量检查结果的报告格式、呈现方式和传递方式，以及 AI 如何使用检查结果、package 横向比较和替代 package 推荐，不属于本用例。

## 特殊需求

无。
