# Skill 中文化迁移规范

## 参考资料

- [文档规范](document.md)
- [能力规范](capability.md)

本文档补充**文档规范**与**能力规范**，用于将现有英语 `Skill` 迁移为以简体中文为默认语言的 `Skill`。

## 迁移目标

- 中文化面向用户和模型的自然语言内容。
- 保持 `Skill` 的职责、调用边界、工作流和输出语义不变。
- 保持稳定标识不变，避免破坏已有调用和引用。
- 通过临时双语核对降低遗漏风险，并在验证完成后清理迁移产物。

## 稳定标识

以下内容默认保持英语，不进行翻译：

- `Skill` 目录名。
- `SKILL.md` front matter 中的 `name`。
- `$skill-name` 调用标识。
- 资源文件名、代码标识符和命令。
- 产品名、协议名、技术名及其约定俗成的关键词。

新增或修改引用时，必须继续使用迁移前的稳定标识。
将可引用文件资源从 `assets/` 归并到 `references/` 属于目录规范化，不改变资源文件名；迁移时必须同步更新全部引用路径。

## 翻译范围

默认翻译以下自然语言内容：

- `SKILL.md` 的 `description` 和正文。
- `references/` 中的说明、模板与示例。
- `agents/openai.yaml` 中面向用户的说明和默认提示。
- 由 `Skill` 生成的文档标题、章节名和说明文字。

翻译应保持原有语义强度。不得因措辞变化而无意改变必填项、可选项、权限边界、停止条件或工作流顺序。

中文化迁移只负责转换已有自然语言内容，不要求在 `SKILL.md` 中新增语言约定或独立的“语言”章节。原 `Skill` 未声明语言切换规则时，不得在迁移过程中引入新的语言行为。

## 临时双语

优先使用 Git 历史核对迁移前内容。用户明确要求临时保留英语版时：

- 将英语快照放在 `Skill` 目录之外，并保留原有相对目录结构。
- 不得在同一个 `Skill` 目录中放置第二个名为 `SKILL.md` 的文件。
- 在迁移任务中明确英语快照的临时性质和清理条件。
- 中文版验证成功后删除英语快照及迁移提示。

临时快照只用于语义核对，不参与运行时发现、引用或调用。

## 调用策略与界面

调用策略由 `agents/openai.yaml` 统一声明。仅允许用户主动调用时使用：

```yaml
policy:
  allow_implicit_invocation: false
```

不要在 `SKILL.md` 正文中重复机器可执行的调用策略。显式调用型 `Skill` 的 `description` 应保持简短，并直接说明 `$skill-name` 调用方式。

需要增强用户识别时，配置 `interface`：

- `display_name` 使用简洁、稳定的英语名称，便于匹配。
- `short_description` 使用简体中文说明核心用途。
- `default_prompt` 使用简体中文，并显式包含 `$skill-name`。
- 没有现成资产时，不为迁移专门创建图标。

## 引用资源与 Skill 一致性

迁移时必须同时检查 `template`、`example`、`SKILL.md` 工作流和审查清单：

- `SKILL.md` 引用的文件资源必须统一放在 `references/` 中，不得单独设立 `assets/` 目录。
- 配套的 `template` 与 `example` 必须位于 `references/` 中。
- 必填章节在 `template` 和 `example` 中都必须出现。
- 可选章节必须明确标注，`example` 可以在有实际价值时展示。
- 章节名称、层级和顺序应保持一致。
- `example` 的核心决策、具体约定和后果不得相互矛盾。
- `SKILL.md` 的输入补全范围必须覆盖所有必填章节。
- 审查清单必须逐项检查必填内容，并单独约束可选内容。

模板中的指导文字和占位符用于起草过程，不得残留在最终产物中。

## 迁移流程

1. 记录迁移前的目录结构、稳定标识、调用策略和文档结构。
2. 按需保存英语快照，并确认快照不会参与 `Skill` 发现。
3. 翻译 `SKILL.md`、参考资料和界面文案，保持稳定标识不变。
4. 对照迁移前内容检查职责、输入、输出、权限和工作流语义。
5. 将 `SKILL.md` 引用的文件资源统一迁移至 `references/`，删除清空后的 `assets/` 目录，并对照 `template`、`example` 与审查清单检查结构一致性。
6. 执行结构、配置、链接和行为验证。
7. 验证成功后删除英语快照、迁移说明和失效引用。
8. 清理后重新执行全部验证。

## 验证要求

每次迁移至少完成以下检查：

- `Skill` front matter、目录名和文件结构通过 `skill-creator` 的校验器。
- `agents/openai.yaml` 可以解析，`interface` 与 `policy` 字段符合约束。
- `short_description` 长度符合界面要求。
- `default_prompt` 包含正确的 `$skill-name`。
- 仓库内 Markdown 链接检查不存在失效链接。
- `SKILL.md` 引用的文件资源全部位于 `references/`，且不存在独立的 `assets/` 目录。
- 配套的 `template` 与 `example` 位于 `references/`。
- `template` 和 `example` 具备相同的必填章节。
- 审查清单覆盖全部必填章节。
- 中文内容保留必要的英语术语、代码标识符、路径和命令。
- `git diff --check` 不报告空白字符错误。

调用行为发生变化时，还必须验证修改前后的可观察行为。例如，显式调用型 `Skill` 应验证普通自然语言请求不会触发，而 `$skill-name` 调用仍能执行完整工作流。

## 完成条件

- 中文版可以独立支持完整工作流。
- 迁移前后的职责和语义边界一致。
- `SKILL.md` 引用的文件资源全部位于 `references/`，且不存在独立的 `assets/` 目录。
- 配套的 `template`、`example`、工作流和审查清单一致。
- 调用策略与界面文案一致。
- 临时英语快照、迁移提示和失效链接已清理。
- 所有验证在清理后重新通过。
