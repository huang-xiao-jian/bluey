# npm-plus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增同时提供 CLI 与 MCP 接口的 `npm-plus` workspace package，按照规格确定精确 npm package 目标并报告依赖规模质量事实。

**Architecture:** `mcps/npm-plus` 采用 CLI-first 分层结构。Core 通过 Registry port 读取 package document、确定目标并检查质量；Infrastructure 使用原生 `fetch` 实现 npm Registry adapter；CLI 和 MCP 通过同一个 composition root 调用工作流并分别映射输出。

**Tech Stack:** TypeScript、Node.js 26、pnpm、Vitest、Commander、Inversify、Zod、MCP SDK、semver、tsdown。

**Spec:** `specs/npm-plus/spec.md`、`specs/npm-plus/design.md`、`specs/npm-plus/interfaces/spec.md`

## Global Constraints

- 使用 `mise exec -- <command>` 运行所有非交互式 Node.js 与 pnpm 命令。
- 新增自然语言文档和代码注释使用简体中文；测试名称和测试代码使用英语。
- Core 不依赖 CLI 或 MCP 协议；CLI 与 MCP 必须调用同一个工作流。
- 仅支持 package 名称、精确版本和 tag；版本范围必须在接口边界被拒绝。
- 成功结果只包含客观事实，不提供评分、评级、采用建议或替代推荐。
- 目标确定错误进入接口错误通道；质量维度异常保留在成功结果的 `quality.exceptions` 中。

```ts
export type InterpretedVersionIdentifier =
  | { readonly kind: "exact"; readonly exactVersion: string }
  | { readonly kind: "tag"; readonly tag: string };

export class PackageVersionIdentifierInterpreter {
  public interpret(value?: string): InterpretedVersionIdentifier {
    if (value === undefined) return { kind: "tag", tag: "latest" };
    const exactVersion = valid(value);
    return exactVersion
      ? { kind: "exact", exactVersion }
      : { kind: "tag", tag: value };
  }
}
```
