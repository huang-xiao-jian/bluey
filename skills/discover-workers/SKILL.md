# 发现业务工人

## 参考资料

- [预定机票用例规约案例](references/use-case/book-flight.md)
- [预订机票业务工人识别案例](references/book-flight-workers.md)
- [业务工人识别输出模板](./references/template.md)

## 输入

用户必须提供清晰的用例规约。

### 异常处理

- 用例规约含糊不清时，拒绝执行，并要求用户提供更清晰的用例规约，不得擅自推断缺失细节。

## 核心原则

1. **职责抽象优先**：业务工人表示业务边界内部对结果负责的稳定职责，不是人员、岗位、部门或技术组件。
2. **抽象与实现分离**：先识别业务工人，不关注系统如何实现该职责。
3. **自动化显式建模**：超时检测、周期处理和规则驱动动作不能因自动执行而被排除，应按业务目的抽象。
4. **依据可追溯**：业务工人、职责边界和实现方式都必须能够回溯到用例规约。

## 工作流

### 1. 提取职责片段

扫描参与者、基本事件流、备选流、异常流、前置条件、后置条件和业务规则，提炼行为相关描述，整理为“前置条件 + 业务动作 + 业务对象 + 结果”，无需保留原始依据。

例如：

- “核验客户身份” → 核验 + 客户身份 + 是否通过
- “录入保单信息” → 录入 + 保单信息 + 形成待审核记录
- “审批赔付方案” → 审批 + 赔付方案 + 通过/拒绝

### 2. 识别抽象职责，寻找候选业务工人

根据“职责片段”细化抽象职责，匹配抽象的责任主题，按业务目标、决策权、执行权和责任分配命名，
命名统一采用英语，必须符合**面向对象**、**自然业务语义**，**禁止采用**实际岗位名或者消息消费者、数据库表等技术实现名称。

外部参与者、外部系统、纯被动接收者和缺乏独立责任结果的临时动作不作为业务工人。

### 3. 职责类型

- 业务目标、决策边界和责任分配相同的职责合并为同一个业务工人。
- 业务目标、决策权或责任分配不同，拆分为不同业务工人。

### 4. 回溯与输出

逐项核对业务目标、职责边界、输入、输出、决策点、异常处理策略。

严格按照 **业务工人识别输出模板** 组织内容。模板中的引用块、HTML 注释、格式指导、示例和占位符只用于起草，不得出现在最终输出中。

## 审查清单

- [ ] 每个业务工人都位于业务边界内部，并承担明确业务目标和结果责任。
- [ ] 名称表达业务职责，不是现实人员、岗位、部门或技术组件名称。
- [ ] 系统内部自动化策略没有遗漏。
- [ ] 相同业务目标、决策边界和结果责任已经合并，不同责任没有被错误合并。
- [ ] 每个业务工人都包含业务目标、职责边界、输入、输出、决策点、异常责任。
- [ ] 最终输出不包含模板说明、注释、格式指导、示例或占位符。
