## 明示规则

- **商品名称长度**：商品名称不得超过 200 个字符。
  - **来源依据**：维护商品 / 业务规则“商品名称长度”；基本事件流步骤 2。
- **商品价格范围**：商品价格必须是大于 0 的整数。
  - **来源依据**：维护商品 / 业务规则“商品价格范围”；基本事件流步骤 2。
- **商品库存范围**：商品库存不得小于 0。
  - **来源依据**：维护商品 / 业务规则“商品库存范围”；基本事件流步骤 2。
- **商品状态互斥**：商品同一时间只能处于草稿、已上架或已下架中的一种状态。
  - **来源依据**：维护商品 / 业务规则“商品状态互斥”；成功场景后置条件步骤 1。
- **商品状态转换**：商品只允许执行“创建 → 草稿 → 已上架 → 已下架 → 草稿”所描述的状态转换。
  - **来源依据**：维护商品 / 业务规则“商品状态转换”；基本事件流步骤 3、5–8；备选事件流“恢复草稿后编辑”步骤 1–2。
- **商品管理权限**：只有商品管理员可以创建、编辑、上架、下架或恢复商品。
  - **来源依据**：维护商品 / 业务规则“商品管理权限”；前置条件步骤 1。
- **商品编辑条件**：只有草稿状态的商品可以编辑。
  - **来源依据**：维护商品 / 业务规则“商品编辑条件”；基本事件流步骤 4；备选事件流“恢复草稿后编辑”步骤 1–3。
- **商品上架条件**：只有草稿状态的商品可以上架。
  - **来源依据**：维护商品 / 业务规则“商品上架条件”；基本事件流步骤 5–6。
- **商品下架条件**：只有已上架状态的商品可以下架。
  - **来源依据**：维护商品 / 业务规则“商品下架条件”；基本事件流步骤 7–8。
- **无效商品不得保存**：商品属性不满足校验条件时，系统不得创建或保存商品。
  - **来源依据**：维护商品 / 异常事件流“商品属性无效”步骤 1–2；失败场景后置条件步骤 1。

## 候选推断规则

- **商品创建结果完整性**：商品创建成功时，商品属性必须全部有效，且商品必须进入草稿状态。
  - **来源依据**：维护商品 / 基本事件流步骤 2–3；成功场景后置条件步骤 1–2。
  - **推导过程**：基本事件流先校验全部商品属性，再创建商品并设置草稿状态；成功后置条件同时要求商品存在、状态有效且属性满足约束，因此这些结果需要在创建成功时共同成立。
